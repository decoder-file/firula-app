# Firula app 1.3.0

Build de loja. Versão 1.3.0 — iOS build 10, Android versionCode 108 (`appVersionSource: local`,
valores do `app.json`). Anterior: 1.2.0 (iOS 9, Android 107).

## O que entra

- **Nome do dono no ingresso** (e4af10b): a lista de "Meus ingressos" e o modal do QR Code mostram
  o nome do participante. Quem confere na portaria vê o nome junto do QR.
- **Analytics com PostHog** (2251242): telas, toques, login/cadastro e o funil de compra
  (evento visto → checkout → compra concluída ou falha), ingressos (QR aberto, carteira).
  Sem dado pessoal: identifica só pelo id da conta; toques não gravam texto nem
  accessibilityLabel; sem session replay. Desligado em desenvolvimento.
- **Campeonatos** (5674258): rodadas na ordem dos jogos e fase final com semifinais cruzadas.
- **Reserva de quadra** (0a396ed): telefone obrigatório na confirmação da reserva.

Tudo é só JavaScript (o `posthog-react-native` não tem código nativo). Como a 1.1.1+ recebe OTA
pelo canal `production`, poderia ir por `eas update`; a versão de loja carimba as novidades e
leva o analytics para quem está em versões antigas.

## Antes de gerar — bloqueante

`yarn release:check` precisa passar. Hoje ele falha:

- **`EXPO_PUBLIC_POSTHOG_KEY` está com a chave pessoal do PostHog (`phx_`)**. Toda variável
  `EXPO_PUBLIC_*` vai embutida no app — conferido num bundle de teste: a chave aparece nele.
  Quem baixar o app conseguiria extrair e usar a conta do PostHog.
  1. Troque pelo **Project token** (`phc_...`): PostHog → Settings → Project → Project token.
  2. A chave `phx_` é a do script do dashboard (`yarn posthog:dashboard`, que a pede na hora) —
     não deve ficar em `.env`. Ela nunca entrou no git (o arquivo não é versionado desde 03/09).
     Se algum build ou `eas update` foi gerado depois de ela ir para o `.env.production`,
     revogue-a no PostHog e crie outra.
  3. Rode `yarn release:check` de novo: deve terminar com "✓ variáveis públicas sem segredos".

Proteção extra no código: o app só liga o analytics com um token `phc_`; qualquer outra coisa é
descartada (`src/analytics/config.ts`).

## Comandos

```bash
cd ~/project/firula/mobile
yarn release:check

# projetos nativos regenerados a partir do app.json (ios/ e android/ são gerados, não versionados)
npx expo prebuild --platform ios --clean
npx expo prebuild --platform android --clean

# iOS: Xcode → Product → Archive → Distribute (App Store Connect). Se o Xcode reclamar do Podfile.lock: cd ios && pod install
# Android: cd android && ./gradlew bundleRelease   (precisa do credentials.json com a upload key)
```
